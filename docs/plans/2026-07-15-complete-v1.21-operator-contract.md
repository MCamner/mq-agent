# v1.21 Operator Contract Completion Implementation Plan

## Goal

Lock the five mq-agent JSON surfaces consumed by mq-hal and add approval-bound stack-loop audit history that mq-hal can display.

## Owner repo

mq-agent

## Secondary repos

mq-hal

## Architecture boundary

- mqobsidian owns context contracts, templates, generators, and published context surfaces.
- mq-agent owns planning, workflow routing, task decomposition, and agent handoff.
- mq-mcp owns execution tools, tool safety, and runtime boundaries.
- mq-hal owns status, operator summaries, release/runbook views.
- repo-signal owns publish readiness, security/readiness scoring, and repo health checks.

Additional boundary for this change:

- mq-agent owns and writes the versioned operator payloads and stack-loop audit records.
- mq-hal reads and renders those records without redefining gates or execution policy.

## Non-goals

- Do not change release readiness, brain-gate, runtime-gate, cockpit, or dashboard decisions.
- Do not make dry-run, preview, idle, or blocked-without-approval loop calls write history.
- Do not let mq-hal execute loop actions, mutate Git state, or write mqobsidian truth.
- Do not bump package versions, create tags/releases, or start v1.22.0.
- Do not remove legacy JSON fields in the v1 contracts.

## Approval gates

- Before file writes: implementation approval required after this plan.
- Before commit: yes, separately for mq-agent and mq-hal.
- Before push/merge: yes, separately for mq-agent and mq-hal.
- Before deletion/settings changes: yes.

## Rollback

- Before commit, restore only the files listed in each task with `git restore`; retain this plan as the execution record.
- After commit, revert the mq-hal consumer commit before reverting the mq-agent producer commit.
- Existing v1 payload fields remain present, so reverting the added schema markers does not require a data migration.
- Audit history is append-only local state under `MQ_AGENT_STATE_DIR`; code rollback does not delete operator records.
