# mq-agent v1.24.0 Release Plan

## Goal

Release only `mq-agent` as `v1.24.0` by dogfooding the PR-mediated release
path: prepare a release PR without tagging, merge it only after review and CI,
then explicitly finalize the verified merge commit.

## Owner repo

mq-agent

## Secondary repos

None. Other MQ repositories are read-only and must not be released in this
pass.

## Architecture boundary

- mqobsidian owns context contracts, templates, generators, and published context surfaces.
- mq-agent owns planning, workflow routing, task decomposition, and agent handoff.
- mq-mcp owns execution tools, tool safety, and runtime boundaries.
- mq-hal owns status, operator summaries, release/runbook views.
- repo-signal owns publish readiness, security/readiness scoring, and repo health checks.
- GitHub owns branch protection, pull-request state, CI state, and the merge commit identity.
- `mq-agent` owns its version surfaces, changelog, release branch, release PR, and final tag.

## Non-goals

- Do not run `stack release --all --execute --approve`.
- Do not release, version-bump, tag, or otherwise modify another repository.
- Do not push directly to `main`.
- Do not merge the release PR automatically.
- Do not create or push `v1.24.0` before the release PR is verified as merged.
- Do not combine prepare, merge, and finalize into one approval gate.

## Approval gates

- Before plan file write: approved by the request for this explicit plan.
- Before release prepare, commit, branch push, and PR creation: yes; one explicit approval for Task 2.
- Before release-PR merge: yes; separate approval after diff review and green CI.
- Before finalization and tag push: yes; separate approval after verified merge.
- Before deletion, force-push, or settings changes: yes; none are planned.

## Verified baseline

- `main` and `origin/main` point at `1bcaf40` after PR #165.
- Working tree is clean.
- `./release-check.sh --dry-run --json` reports `READY` for `1.23.0` with no blockers or warnings.
- `uv run mq-agent stack contract-check --json` reports the stack contracts `READY`.
- `uv run mq-agent stack release --all --preflight --json` reports 8 ready and 0 blocked.
- `uv run pytest tests/test_stack_release.py -q` reports 96 passed.
- The CLI rejects single-repo `--preflight`; single-repo release planning is dry-run by default.
- `uv run mq-agent stack release --repo mq-agent --version 1.24.0 --json` reports `go: true`, no blockers or warnings, and target tag `v1.24.0`.

## Test gates

- `git status --short --branch`
- `git log --oneline -1`
- `./release-check.sh --dry-run --json`
- `uv run mq-agent stack contract-check --json`
- `uv run mq-agent stack release --repo mq-agent --version 1.24.0 --json`
- `uv run pytest tests/test_stack_release.py -q`
- GitHub checks on the release PR must all pass before merge.
- Immediately before finalize, verify the PR base, head, merged state, merge commit, version surfaces, and tag absence.

## Rollback

- Before prepare: no rollback is needed because planning and dry-run are read-only.
- If prepare fails before commit, the command must restore edited version surfaces and the starting branch.
- If prepare creates a branch or draft PR but cannot complete, leave them for review; do not force-push or delete automatically.
- Before merge, close the release PR if the release is cancelled; `main` remains unchanged and no tag exists.
- After merge but before finalize, revert the release PR through a new PR if cancellation is required; do not tag the reverted release.
- After a correct tag is pushed, rollback requires a separate incident decision; this plan does not authorize tag deletion or rewriting.

### Task 1: Confirm the explicit v1.24.0 candidate

**Purpose:** Prove that only `mq-agent` is eligible for the explicit minor release before any mutation.

**Files:**

- Read-only reference: `VERSION`
- Read-only reference: `.mq/repo-contract.json`
- Read-only reference: `CHANGELOG.md`
- Read-only reference: `release-check.sh`

**Steps:**

1. Confirm clean, synced `main` at the expected post-#165 commit.
2. Run the repository release check and contract check.
3. Run the explicit single-repo dry-run for `1.24.0`.
4. Require `go: true`, no blockers, target `v1.24.0`, and `release_mode: pull_request`.
5. Stop before any execute command.

**Commands:**

```bash
git status --short --branch
git log --oneline -1
./release-check.sh --dry-run --json
uv run mq-agent stack contract-check --json
uv run mq-agent stack release --repo mq-agent --version 1.24.0 --json
```

**Expected result:**

The candidate is ready for a repo-specific prepare operation, with no changes,
commit, branch push, PR, or tag created.

**Commit suggestion:**

None; this task is read-only.

### Task 2: Prepare the v1.24.0 release PR

**Purpose:** Create the reviewable release change through the protected PR path without tagging or changing `main`.

**Files:**

- Modify on release branch: `VERSION`
- Modify on release branch: `pyproject.toml`
- Modify on release branch: `uv.lock`
- Modify on release branch: `.mq/repo-contract.json`
- Modify on release branch: `CHANGELOG.md`
- Modify on release branch: `README.md`
- Modify on release branch: `docs/index.html`

**Steps:**

1. Obtain explicit approval for the prepare write flow.
2. Re-run the explicit dry-run immediately before execution.
3. Execute only the single-repo `mq-agent` release for version `1.24.0`.
4. Confirm the result is `PR_OPENED` or `AWAITING_MERGE`.
5. Confirm the starting branch is restored and `main` was not pushed.
6. Confirm no local or remote `v1.24.0` tag exists.
7. Record the release PR number, URL, base, head, and candidate commit.

**Commands:**

```bash
uv run mq-agent stack release --repo mq-agent --version 1.24.0 --json
uv run mq-agent stack release --repo mq-agent --version 1.24.0 --execute --json
git status --short --branch
git tag --list v1.24.0
git ls-remote --tags origin refs/tags/v1.24.0 refs/tags/v1.24.0^{}
```

**Expected result:**

A draft release PR targets `main`; its release branch contains the owned
version and changelog changes. `main` is unchanged and `v1.24.0` does not
exist locally or remotely.

**Commit suggestion:**

`release: v1.24.0`

### Task 3: Review and merge the release PR

**Purpose:** Admit the release commit to `main` only after its exact diff and CI evidence are accepted.

**Files:**

- Read-only review: the seven release surfaces changed by Task 2

**Steps:**

1. Verify the PR changes only the seven expected release surfaces.
2. Verify version consistency is exactly `1.24.0` and release notes describe the PR-mediated release behavior.
3. Verify all required GitHub checks are green and the PR is mergeable.
4. Verify no `v1.24.0` tag exists.
5. Obtain separate approval, mark ready if needed, and merge the release PR.
6. Record the exact GitHub merge commit.

**Commands:**

```bash
gh pr diff <release-pr-number>
gh pr checks <release-pr-number>
gh pr view <release-pr-number> --json state,isDraft,mergeable,baseRefName,headRefName,headRefOid,statusCheckRollup
git ls-remote --tags origin refs/tags/v1.24.0 refs/tags/v1.24.0^{}
```

**Expected result:**

The release PR is merged into `main` after review and green CI. No tag has yet
been created.

**Commit suggestion:**

None; use the repository's configured GitHub PR merge method.

### Task 4: Finalize the verified merge commit

**Purpose:** Create `v1.24.0` only on the exact merge commit verified by the new finalization path.

**Files:**

- Read-only verification: merged release surfaces and GitHub PR metadata
- External write: annotated Git tag `v1.24.0`
- External write: stack truth export produced by successful finalization

**Steps:**

1. Obtain separate approval for finalization and tag push.
2. Fast-forward local `main` and require a clean, synced working tree.
3. Verify GitHub reports the exact release PR merged into `main`.
4. Verify its merge commit contains version `1.24.0` on all owned surfaces.
5. Run explicit finalization for that PR and version.
6. Verify local and remote `v1.24.0` resolve to the recorded merge commit.
7. Re-run finalization only as an idempotency check if explicitly requested.

**Commands:**

```bash
git switch main
git pull --ff-only
git status --short --branch
uv run mq-agent stack release --repo mq-agent --version 1.24.0 --finalize-pr <release-pr-number> --approve --json
git rev-parse v1.24.0^{}
git ls-remote --tags origin refs/tags/v1.24.0 refs/tags/v1.24.0^{}
```

**Expected result:**

The annotated `v1.24.0` tag exists locally and remotely and its peeled commit
is exactly the verified release-PR merge commit.

**Commit suggestion:**

None; finalization tags the already merged commit.
