# v1.22 Inbox Promotion Orchestration Implementation Plan

## Goal

Ship a stable `mq-agent obsidian inbox` workflow that reads canonical
mqobsidian exports, ranks evidence-backed candidates, requires review, and
delegates reversible writes to mqobsidian.

## Owner repo

mq-agent

## Secondary repos

mqobsidian

## Architecture boundary

- mqobsidian owns schemas, policy data, export materialization, promotion
  events, durable records, and mutation commands.
- mq-agent owns discovery, ranking computation, workflow routing, stable JSON,
  and approval enforcement.
- mq-mcp and repo-signal provide evidence; neither owns promotion truth.
- mqlaunch remains a thin delegate and is not changed here.

## Locked design decisions

- The one well-known entrypoint is
  `$MQ_OBSIDIAN_DIR/exports/truth-export-index.json`; every other path is
  discovered from it and must remain vault-relative.
- mqobsidian publishes `promotion-policy.v1`,
  `memory-score-manifest.v1`, and `memory-evidence-manifest.v1` surfaces.
- Policy weights and thresholds are mqobsidian data; the formula and routing
  workflow are mq-agent code.
- Every candidate has a moderator checkpoint. `auto-promotable` means eligible
  for approval, never an unattended write.
- Existing `mq_agent/memory/inbox_pipeline.py` is extended; no second vault or
  delegation pipeline is created.
- State transitions are fixed:

| Verb | From | To | Durable effect |
| --- | --- | --- | --- |
| promote | candidate | promoted | write/update category-mapped learn record |
| reject | candidate | archived | no durable learn record |
| defer | candidate | observed | no durable learn record |
| rollback | promoted | candidate | remove generated learn projection only |
| deprecate | promoted | deprecated | retain record, mark deprecated |

- Evidence refs resolve only through `memory-evidence-manifest.v1`; opaque or
  missing refs block promotion.

## Non-goals

- No fallback to private raw inbox/scores/observations.
- No hardcoded weights, thresholds, or discovered surface paths in mq-agent.
- No generic mqobsidian command pass-through.
- No package-version, release, tag, or mqlaunch changes.

## Approval gates

- Before implementation writes: explicit user approval after this plan.
- Every applied transition: `--confirm`; default is dry-run.
- Commit: separate approval per repo.
- Push/merge: separate approval per repo.
- Deletion/settings: separate approval.

## Cross-repo rollback

- Merge mqobsidian first, mq-agent second.
- If mq-agent fails after mqobsidian merges, leave additive owner contracts in
  place and fix/revert only mq-agent.
- If both must roll back, run `git revert <mq-agent-merge-commit>` first, then
  `git revert <mqobsidian-merge-commit>`; never rewrite shared history.
- Runtime transitions use a write-ahead journal with deterministic recovery;
  recovery never deletes event history and appends compensation events when a
  committed transition must be reversed.

### Task 4: Add atomic transition primitives in mqobsidian

**Purpose:** Implement one tested state machine below the CLI.

**Files:**

- Modify in mqobsidian: `memory/commands/emit_generic_score.py`
- Modify in mqobsidian: `memory/commands/emit_learn_writeback.py`
- Modify in mqobsidian: `memory/commands/tests/test_generic_score.py`
- Modify in mqobsidian: `memory/commands/tests/test_learn_writeback.py`
- Create in mqobsidian: `memory/commands/transition_journal.py`
- Create in mqobsidian: `memory/commands/tests/test_transition_journal.py`
- Modify in mqobsidian: `schemas/promotion-event.v1.json`
- Modify in mqobsidian: `examples/promotion-event.example.json`
- Modify in mqobsidian: `scripts/validate-export.py`

**Steps:**

1. Add the five exact transitions from the locked table.
2. Resolve evidence only from the exported evidence manifest and copy refs into
   an additive `source_evidence_refs` event field.
3. Block illegal state, missing evidence, and unresolved evidence.
4. Write an fsynced intent journal containing prior hashes, staged paths, and
   the requested transition before changing state.
5. Apply deterministic commit steps: score replace, learn projection replace,
   event append as commit marker, then journal completion.
6. On startup, recover incomplete journals: restore hash-verified snapshots
   when no commit event exists; otherwise finish forward. If forward recovery
   cannot complete, append an inverse compensation event and restore prior
   projections. Never truncate the event log.
7. Add fault injection after every commit step and prove a subsequent recovery
   yields either complete old state or complete new state plus audit events.
8. Make rollback remove only the generated learn projection and append an
   inverse event; deprecate retains the record with deprecated status.
