# Post-v1.24 Stabilization Implementation Plan

## Goal

Align single-repo planning and execution with declared release modes, close the
contract-check coverage gap, synchronize operator documentation, and restore a
green lint baseline.

## Owner repo

mq-agent

## Secondary repos

mqobsidian (read-only policy reference)

## Architecture boundary

- mqobsidian owns context contracts, templates, generators, and published context surfaces.
- mq-agent owns planning, workflow routing, task decomposition, and agent handoff.
- mq-mcp owns execution tools, tool safety, and runtime boundaries.
- mq-hal owns status, operator summaries, release/runbook views.
- repo-signal owns publish readiness, security/readiness scoring, and repo health checks.

## Non-goals

- No version bump, tag, GitHub Release, commit, push, merge, or branch cleanup.
- No change to the prepare/finalize mutation sequence beyond shared mode policy.
- No unrelated refactoring.

## Approval gates

- Before file writes: no; approved by the user in this task.
- Before commit: yes.
- Before push/merge: yes.
- Before deletion/settings changes: yes.

## Test gates

- `uv run pytest tests/test_stack_release.py`
- `uv run pytest`
- `uv run ruff check .`
- `./scripts/markdownlint.sh`
- `git diff --check`

## Rollback

Revert only the files listed per task with a normal reverse patch. Do not reset
the worktree or discard unrelated user changes.

**Purpose:** Ensure dry-run and execute use the same release-mode decision.

**Files:**

- Modify: `mq_agent/tools/stack_release.py`
- Modify: `tests/test_stack_release.py`
